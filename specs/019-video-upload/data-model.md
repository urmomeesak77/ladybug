# Phase 1 Data Model: Video Upload

## Entity: Trashpost (existing, extended)

`trashposts` gains one new column; no existing column changes type or meaning.

| Column | Type | Nullable | New? | Meaning for a video post |
|--------|------|----------|------|---------------------------|
| `type` | string | yes | reused | `'video'` (joins existing `'image'` / `'youtube'` / legacy `null`) |
| `file` | string | yes | reused | The video's own filename, `{hash}.{ext}` (`ext` ∈ `mp4`, `webm`) — resolves via `MediaPath::videoRelativePath()`, **not** `imageRelativePath()`, for this type |
| `poster` | string | yes | **new** | The generated poster still's filename, `{hash}.jpg` — resolves via the existing `MediaPath::imageRelativePath()` / size-variant machinery, exactly as an image post's `file` does |
| `metadata` | text (JSON) | yes | reused | `{width, height, ratio, mime}` — width/height/ratio are the poster frame's (== source video's) dimensions; `mime` is the video's (`video/mp4` or `video/webm`), not the poster's |
| `youtube`, `youtube_thumbnail` | string | yes | reused | Always `null` for a video post |

**Migration**: one new migration, `add_poster_to_trashposts_table`, adding nullable
`poster` string after `file`. No index needed (never queried on).

### Column-usage matrix (all three media types, for reference)

| `type` | `file` | `poster` | `youtube` | `youtube_thumbnail` | `metadata.mime` |
|--------|--------|----------|-----------|----------------------|------------------|
| `'image'` | `{hash}.{jpg/png/gif/webp}` | `null` | `null` | `null` | `image/...` |
| `'youtube'` | `null` | `null` | video id | `{videoId}.jpg` | n/a |
| `'video'` (new) | `{hash}.{mp4/webm}` | `{hash}.jpg` | `null` | `null` | `video/...` |

### Validation rules (server-side, `CreatePostRequest`)

- `title`: required, string, ≤255 chars (unchanged, already applies to all types).
- `video`: required when neither `image` nor `youtube` is present; a real uploaded
  file; MIME-sniffed (not filename-sniffed) as `video/mp4` or `video/webm`; ≤20480 KB
  (20 MB); AND passes a deep `ffprobe`-backed decodability check (rejects a corrupt
  file or one whose extension lies about its content — Edge Cases).
- Exactly one of `image` / `youtube` / `video` may be present (three-way mutual
  exclusion, extending the existing two-way `validateExclusivity()`).

### State transitions

Unchanged from the existing model (011/010): a video post is created **pending**
(`activated_at = null`) unless the uploader is admin+ or at/above
`RatingService::TRUST_THRESHOLD` (15), in which case it is activated immediately in the
same transaction as today. Soft-delete / restore / purge / activate / deactivate all
apply identically regardless of `type` — no video-specific moderation state.

## Entity: Video preview image (poster)

Not a new table — a poster is represented purely by the `poster` column plus the
image-tree files it names (research.md item 4). Conceptually:

| Field | Source | Constraint |
|-------|--------|------------|
| Poster filename | `{hash}.jpg`, extracted via `ffmpeg` from the uploaded video | Always `.jpg`, regardless of source container |
| Poster size variants | Generated by the existing `TrashpostImageProcessor` variant logic | Never wider than the source video's own frame width (FR-006, SC-003) — the existing "never upscale" rule applied unchanged |
| Poster storage path | `image/trash/{size}/{shard}/{hash}.jpg` | Same tree/shard rule as any image post |

## API field additions (both public and admin resources)

`TrashpostResource` (`GET /api/posts`, `GET /api/posts/{hash}`, and the `POST
/api/posts` 201 response) adds one field:

| Field | Type | Meaning |
|-------|------|---------|
| `video` | `string \| null` | Public URL of the playable video file; present only when `type === 'video'`, else `null` |

`original` / `default` / `sizes` are reused unchanged — for a video post they describe
the **poster**, exactly as they describe the image for an image post.

`AdminTrashpostResource` (`GET /api/admin/posts`) needs its `thumbnailUrl()` branch
extended: a `type === 'video'` row's thumbnail resolves from `poster`
(`imageRelativePath` on the poster's code/ext), not `file` (which now holds the video
filename and is not an image at all for this type).

## Frontend types (`frontend/src/lib/feedModel.ts`)

`RawPost` gains `video: string | null` (mirrors the new API field).

`FeedMediaKind` gains `'video'`. `FeedMedia`'s video variant carries the same
`src`/`srcset`/`sizes`/`alt`/`width`/`height` poster fields an image variant carries
(computed via the existing `pickImageSource()`/`buildSrcset()`), plus:

| Field | Type | Meaning |
|-------|------|---------|
| `videoSrc` | `string` | The playable video URL (from `raw.video`) |
| `mime` | `string` | `video/mp4` or `video/webm`, derived from the URL extension, for the `<source type>` attribute |

`FeedModel.deriveMedia()` checks `raw.video` first (new), then falls through to the
existing YouTube/image checks unchanged.
